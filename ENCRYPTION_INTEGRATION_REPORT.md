# 🎓 Лекция: Интеграция Шифрования в BOMCategorizer

## 1. Введение: Клиентская сторона безопасности

Мы уже реализовали серверную часть шифрования в `TelegramHelper`. Теперь наша задача — научить клиентское приложение (`BOMCategorizer`) "говорить" на этом защищенном языке.

**Задача:**
Обеспечить безопасную передачу промптов и получение ответов от AI-сервиса, чтобы ни один промежуточный узел (прокси, провайдер) не мог прочитать содержимое ваших запросов.

**Область применения:**
Шифрование работает для **всех запросов к Telegram Bot**:
- ✅ AI поиск PDF документации (`pdf_search.py`)
- ✅ AI классификация компонентов (`ai_classifier.py`)
- ✅ Пользовательские промпты

## 2. Реализация: Шаг за шагом

Мы внедрили поддержку шифрования **AES-256-GCM** прямо в ядро приложения.

### Шаг 1: Модуль шифрования (`bom_categorizer/encryption.py`)

Это "сердце" нашей безопасности. Мы создали универсальный класс `SecureMessenger`, совместимый с серверной реализацией.

**Что он делает?**
1.  **Инициализация ключа:**
    *   Принимает ключ в hex формате (64 символа для 256 бит).
    *   Если ключ не hex, хеширует его через SHA-256.
2.  **Шифрование (Encrypt):**
    *   Генерирует уникальный `Nonce` (12 байт) для каждого запроса.
    *   Шифрует данные через AES-256-GCM (или Fernet как fallback).
    *   Возвращает бинарный пакет: `[Nonce][Шифротекст][Tag]`.
3.  **Расшифровка (Decrypt):**
    *   Извлекает Nonce из начала пакета.
    *   Расшифровывает данные.
    *   Проверяет целостность данных (GCM Tag).
    *   Возвращает чистые данные (bytes или dict).

**Особенности:**
- Использует библиотеку `cryptography` (AES-256-GCM)
- Fallback на Fernet если AES-GCM недоступен
- Поддержка JSON и строковых данных

### Шаг 2: Интеграция в AI Поиск PDF (`gui/pdf_search.py`)

Мы модифицировали класс `AIPDFSearcher`, добавив поддержку шифрования для всех методов работы с Telegram Bot.

**Ключевые изменения:**
*   **Конструктор:**
    *   Добавлены параметры `use_encryption` и `encryption_key`.
*   **Методы `_search_telegram_bot` и `_search_with_custom_prompt_telegram`:**
    *   Проверяют флаг `use_encryption`.
    *   Если включено: шифруют payload через `SecureMessenger`.
    *   Отправляют на endpoint `/ai_query/secure` (вместо `/ai_query`).
    *   Используют формат: `{"data": "base64_encoded_encrypted_payload"}`.
    *   Расшифровывают ответ сервера.
*   **Визуальная индикация:**
    *   В провайдере показывается 🔒 при использовании шифрования.

### Шаг 3: Интеграция в AI Классификатор (`gui/ai_classifier.py`)

Мы модифицировали рабочий поток `AIClassifierWorker`, добавив поддержку шифрования для провайдера `telegram`.

**Ключевые изменения:**
*   **Метод `_classify_telegram`:**
    *   Использует `SecureMessenger` для шифрования промпта.
    *   Отправляет `POST` запрос на endpoint `/ai_query/secure`.
    *   Использует формат: `{"data": "base64_encoded_encrypted_payload"}`.
    *   Расшифровывает ответ от сервера.

### Шаг 4: UI и Настройки (`gui/pdf_search_dialogs.py`)

Добавлен чекбокс "Шифрование" в настройках Telegram Bot.

**Интерфейс:**
*   Чекбокс "Шифрование" в секции Telegram Bot.
*   Поле "Ключ шифрования" активируется при включении шифрования.
*   Настройки сохраняются в `config_qt.json`.

**Передача параметров:**
*   `AISearchWorker` получает `use_encryption` и `encryption_key`.
*   Эти параметры передаются в `AIPDFSearcher`.

### Шаг 5: Конфигурация (`config/config_qt.json.template`)

Мы обновили шаблон конфигурации, чтобы новые пользователи сразу получали правильную структуру настроек.

```json
"api_keys": {
    "telegram_url": "http://localhost:8000/ai_query",
    "telegram_key": "...",
    "telegram_enc_key": "...",
    "telegram_use_encryption": true
}
```

**Поля:**
- `telegram_url` — URL сервера (может заканчиваться на `/ai_query` или базовый URL)
- `telegram_key` — API ключ для аутентификации
- `telegram_enc_key` — Ключ шифрования (hex строка, 64 символа)
- `telegram_use_encryption` — Включить/выключить шифрование (boolean)

## 3. Как это работает "под капотом"?

### Сценарий 1: AI Поиск PDF с шифрованием

Представьте, что вы ищете информацию о компоненте "HMC449" через AI поиск.

1.  **BOMCategorizer (Клиент)**:
    *   Пользователь вводит "HMC449" и нажимает "Найти".
    *   Проверяется флаг `telegram_use_encryption` в настройках.
    *   Если `true`: создается `SecureMessenger` с ключом `telegram_enc_key`.
    *   Формируется payload: `{"prompt": "Найди информацию об HMC449...", "provider": "anthropic", "max_tokens": 4096}`.
    *   Payload шифруется через `messenger.encrypt()` → получается бинарный конверт.
    *   Конверт кодируется в Base64: `"data": "aGVsbG8gd29ybGQ..."`.
    *   Отправляется `POST` на `http://your-server:8000/ai_query/secure`.

2.  **Сеть (Интернет)**:
    *   В Wireshark видно только Base64 строку в JSON поле `data`.
    *   Без ключа расшифровки невозможно понять содержимое.
    *   Промежуточные узлы (прокси, провайдер) видят только зашифрованные данные.

3.  **TelegramHelper (Сервер)**:
    *   Получает запрос на `/ai_query/secure`.
    *   Извлекает `data` из JSON.
    *   Декодирует Base64 → получает бинарный конверт.
    *   Расшифровывает тем же ключом через `SecureMessenger`.
    *   Видит оригинальный промпт.
    *   Отправляет промпт в Claude/GPT через Telegram Bot API.
    *   Получает ответ: `{"response": "HMC449 - это частотный делитель..."}`.
    *   Шифрует ответ и отправляет обратно в формате `{"data": "base64..."}`.

4.  **BOMCategorizer (Клиент)**:
    *   Получает зашифрованный ответ.
    *   Декодирует Base64 и расшифровывает.
    *   Показывает результат пользователю.
    *   В провайдере отображается: `Telegram Bot (anthropic: claude-3-sonnet) 🔒`.

### Сценарий 2: Без шифрования (для сравнения)

Если `telegram_use_encryption = false`:

1.  Payload отправляется как обычный JSON: `{"prompt": "...", "provider": "anthropic"}`.
2.  Endpoint: `/ai_query` (без `/secure`).
3.  В Wireshark видно весь текст промпта в открытом виде.
4.  Ответ приходит как обычный JSON.

### Технические детали

**Формат зашифрованного запроса:**
```json
{
  "data": "aGVsbG8gd29ybGQ..."  // Base64-encoded encrypted payload
}
```

**Формат зашифрованного ответа:**
```json
{
  "data": "cmVzcG9uc2UgdGV4dA..."  // Base64-encoded encrypted response
}
```

**Endpoint mapping:**
- Без шифрования: `/ai_query`
- С шифрованием: `/ai_query/secure`
- Автоматическое преобразование: если URL заканчивается на `/ai_query`, заменяется на `/ai_query/secure`.
