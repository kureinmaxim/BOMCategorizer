## Введение

**BOM Categorizer** — это инструмент для автоматической классификации электронных компонентов из файлов BOM (Bill of Materials). Программа позволяет гибко настраивать правила классификации без необходимости изменения программного кода.

### Основные возможности

- ✅ **Автоматическая классификация** компонентов по категориям
- ✅ **База ИВП** для хранения правил классификации
- ✅ **Интерактивная классификация** для новых компонентов
- ✅ **Экспорт/импорт** базы ИВП через Excel
- ✅ **Резервное копирование** базы данных
- ✅ **Статистика** по категориям компонентов

---

## Принципы работы системы классификации

### Порядок приоритетов

При классификации компонентов программа использует следующий порядок приоритетов:

#### 1. База ИВП (Database) — **Высший приоритет** 🏆

Если компонент найден в базе знаний, он будет классифицирован **строго согласно записи в базе**, игнорируя автоматические правила.

**Преимущества:**
- Точная классификация без ошибок
- Возможность переопределить автоматические правила
- Быстрая работа (прямой поиск в базе)

**Пример:**
```
База ИВП содержит: "LM358" → "ics"
Результат: Компонент "LM358" всегда будет классифицирован как "Микросхемы"
```

#### 2. Автоматические правила — **Вторичный приоритет** 🤖

Если компонента нет в базе знаний, программа пытается определить категорию автоматически по:
- **Ключевым словам** в названии (например, "resistor", "capacitor")
- **Префиксам** производителей (например, "LM" → микросхемы, "1N" → диоды)
- **Паттернам** в названии (например, "R" + число → резистор)
- **Контексту** использования

**Пример:**
```
Компонент "R1-10k" не найден в базе
Автоматическое правило: "R" + число → "resistors"
Результат: Классифицирован как "Резисторы"
```

### Как работает система

```
┌─────────────────────────────────────┐
│   Компонент из BOM файла            │
└──────────────┬──────────────────────┘
               │
               ▼
    ┌──────────────────────┐
    │  Поиск в базе знаний │
    └──────────┬───────────┘
               │
        ┌──────┴──────┐
        │             │
        ▼             ▼
    Найден?      Не найден?
        │             │
        │             ▼
        │    ┌──────────────────┐
        │    │ Автоматические   │
        │    │ правила          │
        │    └────────┬─────────┘
        │             │
        ▼             ▼
    ┌─────────────────────────┐
    │  Классификация          │
    │  (Категория определена) │
    └─────────────────────────┘
```

### Важно понимать

- **База ИВП имеет приоритет** над автоматическими правилами
- Чтобы исправить ошибку классификации, достаточно добавить правильную запись в базу ИВП
- Автоматические правила используются только для новых, неизвестных компонентов

## Интерактивная классификация компонентов

### Когда использовать

Интерактивная классификация используется для компонентов, которые программа не может классифицировать автоматически. Такие компоненты попадают в категорию **"Не распределено"**.

### Пошаговая инструкция

#### Шаг 1: Запуск обработки

1. Загрузите BOM-файл в программу
2. Нажмите кнопку **"🚀 Запустить обработку"**
3. Дождитесь завершения обработки

#### Шаг 2: Открытие интерактивной классификации

1. После завершения обработки нажмите кнопку **"🎯 Интерактивная классификация"**
2. Откроется диалоговое окно со списком нераспределенных компонентов

#### Шаг 3: Классификация компонентов

В открывшемся окне вы увидите:

- **Список компонентов** — все нераспределенные компоненты из текущего файла
- **Кнопки категорий** — для быстрого выбора категории
- **Горячие клавиши** — для еще более быстрой классификации

**Как классифицировать:**

1. Выберите компонент из списка (клик мыши или стрелки на клавиатуре)
2. Выберите категорию одним из способов:
   - Нажмите кнопку с названием категории
   - Используйте горячую клавишу (обычно первая буква категории)
3. Компонент будет перемещен в выбранную категорию
4. Переходите к следующему компоненту

#### Шаг 4: Сохранение результатов

- **Важно:** Ваш выбор **автоматически сохраняется** в базу ИВП
- После завершения диалога компоненты в текущем файле будут автоматически перемещены в выбранные категории
- При следующей обработке похожих файлов эти компоненты будут классифицироваться автоматически

### Пример использования

```
Исходная ситуация:
- Обработано 150 компонентов
- 10 компонентов попали в "Не распределено"

Действия:
1. Открыть "Интерактивная классификация"
2. Классифицировать 10 компонентов:
   - "HMC449" → СВЧ модули (rf_modules)
   - "LM358" → Микросхемы (ics)
   - "Custom-Board-v2" → Отладочные платы (dev_boards)
   - и т.д.

Результат:
- Все 10 компонентов классифицированы
- Правила сохранены в базу ИВП
- При следующей обработке эти компоненты будут определяться автоматически
```

### Советы по эффективной работе

- ✅ Используйте горячие клавиши для ускорения процесса
- ✅ Классифицируйте компоненты последовательно, не пропуская
- ✅ Если не уверены в категории, выберите "Другие" — можно будет исправить позже
- ✅ После классификации запустите обработку заново, чтобы увидеть результат

## Управление базой ИВП

База ИВП — это центральное хранилище правил классификации. Она хранится в файле `component_database.json` и может редактироваться несколькими способами.

### Расположение базы данных

База данных находится в папке приложения:
- **Windows:** `%APPDATA%\BOMCategorizer\component_database.json`
- **macOS:** `~/Library/Application Support/BOMCategorizer/component_database.json`
- **Linux:** `~/.config/BOMCategorizer/component_database.json`

### Экспорт и импорт через Excel

Этот способ рекомендуется для большинства пользователей, так как позволяет массово редактировать правила в привычном интерфейсе Excel.

#### Экспорт базы ИВП

1. В главном меню программы выберите **База данных → 📤 Экспорт в Excel**
2. Выберите место для сохранения файла
3. Файл будет сохранен как `component_database_export.xlsx`

#### Структура файла Excel

Файл содержит две колонки:

| Component Name | Category |
|----------------|----------|
| LM358 | ics |
| 1N4148 | semiconductors |
| HMC449 | rf_modules |

- **Component Name** — точное наименование компонента (как в BOM файле)
- **Category** — код категории (см. [Справочник категорий](#справочник-категорий-компонентов))

#### Редактирование в Excel

**Чтобы исправить ошибку классификации:**

1. Откройте файл `component_database_export.xlsx` в Excel
2. Используйте поиск (Ctrl+F / Cmd+F) для быстрого поиска компонента
3. Найдите нужный компонент в колонке `Component Name`
4. Измените значение в колонке `Category` на правильное
5. Сохраните файл

**Чтобы добавить новое правило:**

1. Добавьте новую строку в конец таблицы
2. В колонке `Component Name` впишите **точное** наименование компонента (как оно указано в BOM файле)
3. В колонке `Category` впишите код категории
4. Сохраните файл

**Пример добавления:**

```
Component Name          | Category
------------------------|------------
LM358                   | ics
HMC449RXZ               | rf_modules  ← новая запись
Custom-Board-v3         | dev_boards  ← новая запись
```

#### Импорт изменений

1. В программе выберите **База данных → 📥 Импорт из Excel**
2. Выберите отредактированный файл `component_database_export.xlsx`
3. Программа обновит базу ИВП
4. **Важно:** Запустите обработку BOM-файла заново ("🚀 Запустить обработку"), чтобы изменения вступили в силу

### Прямое редактирование JSON

Этот способ предназначен для опытных пользователей, которые предпочитают работать с текстовыми файлами напрямую или используют системы контроля версий (Git).

#### Открытие файла базы данных

1. В главном меню программы выберите **База данных → 📁 Открыть папку БД**
2. Откроется папка с файлом `component_database.json`
3. **Важно:** Создайте резервную копию файла перед редактированием!

#### Формат файла

Файл имеет следующую структуру:

```json
{
  "version": "1.0.0",
  "metadata": {
    "created": "2024-01-01",
    "last_updated": "2024-11-20",
    "total_components": 150
  },
  "components": {
    "LM358": "ics",
    "1N4148": "semiconductors",
    "HMC449RXZ": "rf_modules",
    "Custom-Board-v2": "dev_boards"
  }
}
```

#### Редактирование правил

**Чтобы исправить ошибку:**

1. Найдите название компонента в разделе `"components"`
2. Измените значение категории на нужное (используйте коды из [справочника категорий](#справочник-категорий-компонентов))

**Пример:**
```json
// Было:
"HMC449": "others",

// Стало:
"HMC449": "rf_modules",
```

**Чтобы добавить новое правило:**

1. Добавьте новую строку в раздел `"components"`:
```json
"components": {
  "LM358": "ics",
  "Новый компонент": "category_code",  ← новая запись
  "Другой компонент": "category_code"   ← новая запись
}
```

2. **Важно:** Не забудьте запятую в конце строки (кроме последней строки в объекте)

#### Сохранение и применение изменений

1. Сохраните файл (Ctrl+S / Cmd+S)
2. Перезапустите программу или запустите обработку заново
3. Изменения вступят в силу

> ⚠️ **Внимание:** При прямом редактировании JSON строго соблюдайте синтаксис:
> - Все строки должны быть в двойных кавычках
> - Запятые должны быть после каждой пары ключ-значение (кроме последней)
> - Открывающие и закрывающие фигурные скобки должны совпадать
> 
> Ошибка в синтаксисе приведет к невозможности загрузить базу данных. В этом случае используйте резервную копию.

### Резервное копирование

Перед внесением значительных изменений в базу ИВП **настоятельно рекомендуется** создать резервную копию.

#### Создание резервной копии

1. В главном меню программы выберите **База данных → 💾 Резервное копирование**
2. Выберите место для сохранения резервной копии
3. Файл будет сохранен с текущей датой и временем в имени (например, `component_database_backup_2024-11-20_15-30-00.json`)

#### Восстановление из резервной копии

Если что-то пошло не так:

1. Найдите файл резервной копии
2. Скопируйте его в папку базы данных
3. Переименуйте в `component_database.json` (заменив текущий файл)
4. Перезапустите программу

#### Автоматическое резервное копирование

Программа автоматически создает резервные копии при:
- Импорте из Excel
- Массовых изменениях базы данных

## Справочник категорий компонентов

Ниже приведен полный список категорий с их кодами и описаниями. Используйте эти коды при редактировании базы ИВП.

### Основные категории

#### `resistors` — Резисторы
**Описание:** Пассивные компоненты, ограничивающие ток в цепи.

**Примеры компонентов:**
- R1-10k, R2-1M
- Резисторы SMD
- Переменные резисторы (потенциометры)

**Ключевые слова:** R, RES, RESISTOR

---

#### `capacitors` — Конденсаторы
**Описание:** Пассивные компоненты для накопления электрического заряда.

**Примеры компонентов:**
- C1-100uF, C2-10nF
- Керамические конденсаторы
- Электролитические конденсаторы

**Ключевые слова:** C, CAP, CAPACITOR

---

#### `inductors` — Индуктивности (дроссели)
**Описание:** Пассивные компоненты, накапливающие энергию в магнитном поле.

**Примеры компонентов:**
- L1-10uH, L2-100mH
- Дроссели
- Катушки индуктивности

**Ключевые слова:** L, IND, INDUCTOR, CHOKE

---

#### `ics` — Микросхемы
**Описание:** Интегральные схемы (чипы) различного назначения.

**Примеры компонентов:**
- LM358, LM555, ATmega328
- Микроконтроллеры
- Операционные усилители
- Логические микросхемы

**Ключевые слова:** IC, CHIP, MCU, MICROCONTROLLER

---

#### `semiconductors` — Полупроводники
**Описание:** Диоды, транзисторы и другие полупроводниковые компоненты.

**Примеры компонентов:**
- 1N4148 (диод)
- 2N2222 (транзистор)
- LED (светодиод)
- MOSFET, IGBT

**Ключевые слова:** DIODE, TRANSISTOR, LED, MOSFET

---

#### `connectors` — Разъемы и соединители
**Описание:** Механические компоненты для соединения проводов и плат.

**Примеры компонентов:**
- USB разъемы
- Клеммные колодки
- Штыревые разъемы (headers)
- Разъемы питания

**Ключевые слова:** CONNECTOR, HEADER, JACK, PLUG

---

#### `cables` — Кабели и провода
**Описание:** Проводники для передачи сигналов и питания.

**Примеры компонентов:**
- USB кабели
- Кабели питания
- Провода
- Шлейфы

**Ключевые слова:** CABLE, WIRE, CORD

---

#### `dev_boards` — Отладочные платы
**Описание:** Готовые платы для разработки и прототипирования.

**Примеры компонентов:**
- Arduino
- Raspberry Pi
- Отладочные платы производителей
- Evaluation boards

**Ключевые слова:** BOARD, DEV BOARD, EVAL BOARD

---

#### `optics` — Оптика
**Описание:** Оптические компоненты и датчики.

**Примеры компонентов:**
- Фоторезисторы
- Оптопары
- Оптические датчики
- Лазеры

**Ключевые слова:** OPTIC, PHOTO, SENSOR, LASER

---

#### `rf_modules` — СВЧ модули
**Описание:** Модули для работы с радиочастотными сигналами.

**Примеры компонентов:**
- HMC449, HMC441
- RF усилители
- Смесители частот
- Модули Bluetooth/Wi-Fi

**Ключевые слова:** RF, HMC, MIXER, AMPLIFIER

---

#### `power_modules` — Модули питания
**Описание:** Модули и компоненты для преобразования и стабилизации питания.

**Примеры компонентов:**
- DC-DC преобразователи
- Линейные стабилизаторы (LDO)
- Импульсные стабилизаторы
- Модули питания

**Ключевые слова:** POWER, REGULATOR, CONVERTER, LDO

---

#### `our_developments` — Наши разработки
**Описание:** Компоненты и модули, разработанные вашей организацией.

**Примеры компонентов:**
- Custom-Board-v2
- Наши модули
- Специфичные разработки

**Ключевые слова:** CUSTOM, OUR, DEVELOPMENT

---

#### `others` — Другие компоненты
**Описание:** Компоненты, которые не подходят ни под одну из вышеперечисленных категорий.

**Примеры компонентов:**
- Кварцевые резонаторы
- Кнопки и переключатели
- Корпуса
- Термисторы

**Использование:** Используйте эту категорию, если не уверены в правильной классификации.

---

#### `non_bom` — Не входит в BOM
**Описание:** Служебные строки, которые не являются компонентами (заголовки, примечания и т.д.).

**Примеры:**
- Заголовки таблиц
- Комментарии
- Пустые строки
- Служебная информация

**Важно:** Эти строки не будут учитываться при подсчете компонентов.

## Примеры использования

### Пример 1: Первичная настройка базы ИВП

**Задача:** После первой обработки BOM-файла 20 компонентов попали в "Не распределено".

**Решение:**

1. Откройте "Интерактивная классификация"
2. Классифицируйте все 20 компонентов:
   ```
   HMC449 → СВЧ модули
   LM358 → Микросхемы
   Custom-Board → Отладочные платы
   ...
   ```
3. Правила автоматически сохранятся в базу ИВП
4. При следующей обработке эти компоненты будут определяться автоматически

---

### Пример 2: Исправление ошибки классификации

**Задача:** Компонент "HMC449" неправильно классифицирован как "Другие" вместо "СВЧ модули".

**Решение через Excel:**

1. **База данных → Экспорт в Excel**
2. Откройте файл в Excel
3. Найдите "HMC449" (Ctrl+F)
4. Измените категорию с `others` на `rf_modules`
5. Сохраните файл
6. **База данных → Импорт из Excel**
7. Выберите отредактированный файл
8. Запустите обработку заново

**Решение через JSON:**

1. **База данных → Открыть папку БД**
2. Откройте `component_database.json` в текстовом редакторе
3. Найдите строку:
   ```json
   "HMC449": "others",
   ```
4. Измените на:
   ```json
   "HMC449": "rf_modules",
   ```
5. Сохраните файл
6. Перезапустите программу

### Пример 3: Массовое добавление правил

**Задача:** Нужно добавить 50 новых компонентов в базу ИВП.

**Решение:**

1. **База данных → Экспорт в Excel**
2. Откройте файл в Excel
3. Добавьте 50 новых строк в конец таблицы:
   ```
   Component Name    | Category
   ------------------|------------
   Новый компонент 1 | ics
   Новый компонент 2 | resistors
   ...
   ```
4. Сохраните файл
5. **База данных → Импорт из Excel**
6. Выберите файл
7. Все 50 компонентов будут добавлены в базу ИВП

### Пример 4: Работа с несколькими BOM файлами

**Задача:** Обработать несколько BOM файлов с похожими компонентами.

**Решение:**

1. Обработайте первый файл
2. Используйте "Интерактивная классификация" для новых компонентов
3. Правила сохранятся в базу ИВП
4. При обработке следующих файлов компоненты будут определяться автоматически
5. Для каждого нового файла классифицируйте только действительно новые компоненты

**Результат:** С каждым файлом база ИВП растет, и ручная работа уменьшается.

## Часто задаваемые вопросы (FAQ)

### Общие вопросы

**Q: Как программа определяет категорию компонента?**

A: Сначала программа ищет компонент в базе знаний. Если найден — используется категория из базы. Если не найден — применяются автоматические правила (по ключевым словам, префиксам и т.д.).

---

**Q: Можно ли изменить автоматические правила?**

A: Автоматические правила зашиты в программу, но вы можете переопределить их, добавив компонент в базу ИВП с нужной категорией.

---

**Q: Что делать, если компонент классифицирован неправильно?**

A: Добавьте правильную запись в базу ИВП (через Excel или JSON). При следующей обработке компонент будет классифицирован правильно.

---

### Работа с базой ИВП

**Q: Где хранится база ИВП?**

A: В папке приложения:
- Windows: `%APPDATA%\BOMCategorizer\`
- macOS: `~/Library/Application Support/BOMCategorizer/`
- Linux: `~/.config/BOMCategorizer/`

---

**Q: Можно ли использовать одну базу ИВП на нескольких компьютерах?**

A: Да, скопируйте файл `component_database.json` на другой компьютер в соответствующую папку.

---

**Q: Что делать, если база ИВП повреждена?**

A: Используйте резервную копию. Если резервной копии нет, создайте новую базу через "Интерактивную классификацию".

---

**Q: Как часто нужно делать резервное копирование?**

A: Рекомендуется делать резервную копию перед массовыми изменениями. Программа также автоматически создает резервные копии при импорте из Excel.

---

### Интерактивная классификация

**Q: Обязательно ли классифицировать все компоненты сразу?**

A: Нет, можно классифицировать только часть компонентов и закрыть окно. Остальные останутся в "Не распределено" до следующей обработки.

---

**Q: Можно ли изменить категорию компонента после интерактивной классификации?**

A: Да, отредактируйте базу ИВП (через Excel или JSON) и запустите обработку заново.

---

**Q: Сохраняются ли правила при закрытии программы?**

A: Да, все правила автоматически сохраняются в базу ИВП сразу после выбора категории.

---

### Категории компонентов

**Q: Что делать, если компонент не подходит ни под одну категорию?**

A: Используйте категорию `others` (Другие компоненты). В будущем можно будет создать новую категорию или переклассифицировать компонент.

---

**Q: Можно ли создать свою категорию?**

A: В текущей версии программы используются предопределенные категории. Для создания новых категорий требуется изменение программного кода.

---

**Q: В чем разница между "Микросхемы" и "Полупроводники"?**

A: "Микросхемы" (ics) — это интегральные схемы (чипы). "Полупроводники" (semiconductors) — это дискретные компоненты (диоды, транзисторы).

### Статистика базы данных

Просмотр статистики по базе знаний:

После обработки BOM-файла результаты можно экспортировать в различные форматы:

- **Excel** — для дальнейшей обработки в таблицах
- **PDF** — для печати и документирования
- **TXT** — для текстовых редакторов

### Режимы работы

Программа поддерживает три режима работы:

- **Простой режим** — базовые функции классификации
- **Расширенный режим** — все функции, включая сравнение BOM
- **Экспертный режим** — дополнительные настройки и инструменты

Переключение режимов: **Вид → Режим работы**
