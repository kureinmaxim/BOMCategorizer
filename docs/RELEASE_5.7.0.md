# Modern Edition 5.7.0 — исправления анализа ЭРИ, ТРУ и РКМ

Дата: 06.10.2026. Подготовлены исходники для сборки инсталлятора пользователем.
Версия Modern поднята с 5.6.3 до 5.7.0 в шаблоне конфигурации, локальном
app_info, резервной конфигурации и deployment/installer_qt.iss. Standard остаётся
3.3.0; исправления общего ядра применяются и при запуске этой редакции из исходников.
Инсталлятор в этой работе не собирался и установленное приложение не проверялось.

## Изменения

- Коды собственных разработок распознаются в формах `ДЕ1`, `ДЕ-1`, `ДЕ 1.234`,
  `DE1`, `Е1` и с номером словами (`ДЕ один`, `ДЕ пять`). Такие строки попадают
  на лист «Наши разработки», а исходный код сохраняется в `ТУ/Производитель`.
- Сопоставление ТРУ выполняется по полному нормализованному обозначению.
  Разные исполнения, допуски, напряжения и значимые суффиксы не считаются одной
  деталью по похожести. Неоднозначность ERP, ТУ, типа разъёма и единицы измерения
  не разрешается порядком строк. Документированные варианты раскладки и записи
  десятичных номиналов продолжают поддерживаться.
- ERP несопоставленных строк остаётся связанным со своей строкой. Один запас
  ТРУ распределяется между потребителями и листами одного BOM, а не расходуется
  заново на каждом листе. Распределение сохраняет стоимость с точностью до копейки.
  Разные BOM-файлы в GUI по-прежнему обрабатываются как отдельные задачи; для
  общей потребности сначала объедините их в один BOM.
- Явный ноль, дробные количества, пробелы и неразрывные пробелы в числах
  обрабатываются без обрезания. Строковые количества суммируются арифметически.
  Множитель и сравнение читают штатную колонку «шт.». Непонятное количество
  при сопоставлении помечается как требующее проверки.
- Разные отдельные MPN, ТУ и единицы не объединяются только из-за одинакового
  описания; этот контроль сохраняется и на этапе форматирования Excel.
  Короткие реальные обозначения не отбрасываются только из-за длины.
- Исправлены TXT без количества, явные нули DOCX, кириллические диапазоны
  позиционных обозначений, сохранение первичных примечаний для подборов и
  исключение таблиц регистрации изменений. SUMMARY учитывает штатную стоимость.
- Старые DOC читаются через отдельный экземпляр Microsoft Word: оригинал открыт
  только для чтения, макросы отключены, преобразование выполняется во временной
  папке. Требуются установленный Word и pywin32; для Windows зависимость добавлена
  в requirements.txt и уже присутствует в requirements_install.txt. DOCX не требует
  Word. Ошибка чтения Word останавливает задачу, чтобы не выдавать неполный перечень.
- Повторное чтение ТРУ исключает строку ИТОГО и сохраняет найденную единицу БЕИ.
- РКМ сохраняет единицы, поставщиков и различающиеся цены. Нулевой план не
  заменяется ненулевыми историческими данными. Уже обработанная плоская РКМ
  распознаётся по заголовкам; первая позиция сохраняется даже при повреждённой
  колонке нумерации. Устаревшие тесты интеграционного входа и формата базы
  приведены к действующим интерфейсам.

## Сборка и ручная приёмка

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe tools/update_version.py sync
.\.venv\Scripts\python.exe deployment/build_installer.py
```

Выберите Modern Edition (пункт 2). Ожидаемое имя установщика:
`BOMCategorizerModernSetup.exe`. Проверяйте свежесобранный файл: прежний EXE
в корне проекта автоматически не обновляется от изменения исходников.

После установки:

1. В «О приложении» проверьте **5.7.0 / 06.10.2026** и сохранность личных настроек.
2. Обработайте четыре документа по отдельности и совместно. Проверьте позиции,
   подборы, примечания и режим исключения подборов. Старые DOC требуют Word.
3. Подготовьте три исходных XLS заново. Проверьте количества 16, 14, 81 и отсутствие
   ИТОГО в предметных строках при повторном чтении.
4. Объедините BOM с ТРУ. Проверьте ERP, остатки/запасы, нулевые и дробные количества,
   отсутствие повторного расхода одной ТРУ между листами. Несопоставленные позиции
   проверяйте отдельно: похожее название больше не гарантирует автоматическое совпадение.
5. Обработайте PKM_2026_rkm.xlsx. Ожидаются 340 позиций и итог 12 657 905,61.
   Этот файл уже потерял единицы в предыдущей обработке; пустая колонка единиц
   и сообщение о сверке с оригиналом — ожидаемое поведение, а не восстановленные «шт.».
6. Сравните два результата с намеренно изменённым количеством; изменение должно
   появиться в отчёте. Откройте итоговые XLSX в Excel и проверьте формулы, PDF и печать.

## Границы проверки

Результаты не заменяют утверждённый эталон соответствий ЭРИ–ТРУ. Новое
сопоставление намеренно требует полного обозначения: совпадений может стать меньше.
Не утверждены правила аналогов, совместного учёта основной/корректирующей ТРУ,
периодов РКМ и выбора плана/факта. Сохранён прежний приоритет заполненного плана
перед историческими полями, но явный ноль теперь считается данными.
Утраченные единицы старой плоской РКМ не восстанавливаются по названию детали.
GUI, PDF, Excel-пересчёт формул, установка и обновление требуют ручной приёмки.

Для повторения сквозной проверки исходных документов:

```powershell
.\.venv\Scripts\python.exe tests/algorithm_audit/run_offline.py --script tests/algorithm_audit/verify_release_570.py
```

Сценарий использует локальный Word для DOC, отдельную копию базы и блокирует
исходящие Python-соединения. Все результаты записываются в папку доказательств,
оригинальные документы не перезаписываются.
